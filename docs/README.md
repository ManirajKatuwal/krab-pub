## Contributing to these docs

- Put new documents in the directory matching their **purpose**, not their topic:
  a walkthrough is a guide even if it is about security.
- Use relative links between documents so they resolve on GitHub and locally.
- A configuration change updates [`.env.example`](../.env.example) **and**
  [reference/environment.md](reference/environment.md).
- An endpoint change updates [reference/api.md](reference/api.md).
- An architectural decision gets an ADR, not a paragraph buried in a guide.
- Internal-only material belongs in `internal/`, which is gitignored — never
  make it the only home for something a user needs.
